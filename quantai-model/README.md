# QuantAI model foundation

QuantAI's model should specialize in **research-methods guidance and routing analysis requests to QuantAI's existing tools**. It must not replace the statistical engine or invent numerical results.

## Current status

This directory is a reproducible starting point, not a claim that a trained model already exists. The included examples are synthetic development fixtures. They are not enough to establish research-grade performance. Before a public release, expand the training set with reviewed examples and pass the held-out evaluation gates below.

## Architecture

1. **Browser (GitHub Pages):** reads CSV/Excel locally and computes analyses using the existing deterministic QuantAI engine.
2. **Cloudflare Worker:** validates requests, keeps provider credentials server-side, sends only the existing summary/context and conversation to the assistant, and validates/falls back between providers.
3. **QuantAI specialist model:** a small instruction model fine-tuned with LoRA on research-methods questions and structured action-routing examples. Initial base: `Qwen/Qwen3-4B-Instruct-2507` (Hugging Face lists Apache-2.0; retain the licence and review derivative obligations before redistribution).
4. **Deterministic execution:** the model may request a supported action; QuantAI validates it and runs the existing JavaScript engine. All estimates, confidence intervals, p-values, model diagnostics and charts remain engine-generated.
5. **Evaluation:** held-out cases measure valid JSON, action routing, exact action parameters, unsupported claims, and regression tests against the existing engine.

## Low-cost development

- Start with the small 4B base and LoRA adapters rather than pretraining a model from scratch.
- Use a free notebook GPU when available; otherwise run dataset checks and evaluation on CPU and defer training.
- Keep the fine-tuned adapter separate from the base model and record its base revision, dataset version, training configuration and evaluation report.
- Do not assume Hugging Face Inference Providers will serve a custom fine-tuned adapter automatically. Hosting and costs depend on the selected deployment path. See [Hugging Face fine-tuning](https://huggingface.co/docs/transformers/training) and [Inference Providers pricing](https://huggingface.co/docs/inference-providers/pricing).

## Data versions

| Version | Files | What the model sees |
|---|---|---|
| v3 | `data/train.jsonl` (93), `data/eval.jsonl` (32) | A short hand-written `Context: variables are …` prompt. The app never sends this format. |
| v4 | `data/v4/train.jsonl` (1,121), `data/v4/eval.jsonl` (235) | The exact chat context QuantAI's browser sends, built by `prompting.py` like the local API. |

v4 is generated by `datagen/` and described in [`data/v4/README.md`](data/v4/README.md). Every v4 action was executed in QuantAI's real engine before it was kept, and held-out rows use research scenarios and wording never used for training. Keep v3 files unchanged so earlier results stay reproducible.

## Validate the examples first

The validator checks structure, the action contract, minimum counts, exact and near-duplicate overlap between splits and, for v4, that no held-out scenario appears in training. `datagen/audit.py` checks every v4 action against QuantAI's engine rules (model suits outcome type, offsets only with Poisson, clustering only with the mixed model, every variable visible in the context, no invented numbers in replies). Neither proves the examples are scientifically complete.

```bash
python validate_data.py --train data/v4/train.jsonl --eval data/v4/eval.jsonl
python datagen/audit.py data/v4/train.jsonl data/v4/eval.jsonl
pytest -q test_pipeline_v4.py
```

## Train

Use Python 3.10 or 3.11 in a GPU notebook or machine with sufficient memory. The notebook `QuantAI_Training.ipynb` runs every step below in Colab.

```bash
cd quantai-model
python -m venv .venv
# Windows: .venv\Scripts\activate     macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
# standard run: an even 650-row sample (~3 h on a T4); use --max-train-rows 0 for all rows (~5 h)
python train_lora.py --train data/v4/train.jsonl --eval data/v4/eval.jsonl \
  --output outputs/quantai-qwen3-4b-lora-v4 --epochs 1 --max-train-rows 650 --resume
```

Prompts are built by `prompting.py`, the same module `serve.py` uses, so training and serving see identical input. Rows are never truncated: if one exceeds `--max-length` (default 3,584 tokens) training stops with a message. The run writes `training_manifest.json` (data hashes, settings, library versions) next to the adapter. A 4B model may be too large for a CPU-only laptop. Do not commit access tokens or model weights.

## Evaluate

```bash
# fine-tuned v4 adapter
python evaluate.py --model outputs/quantai-qwen3-4b-lora-v4 --cases data/v4/eval.jsonl --report outputs/v4-evaluation.json
# untouched base model with the same instructions
python evaluate.py --baseline-only --cases data/v4/eval.jsonl --report outputs/base-evaluation-v4set.json
# v3 adapter as it would be served (v3 prompt)
python evaluate.py --model outputs/quantai-qwen3-4b-lora-v3 --prompt-version v3 --cases data/v4/eval.jsonl --report outputs/v3-evaluation-v4set.json
```

`scoring.py` reports contract validity, strict and lenient action match with 95% confidence intervals, field-level accuracy (outcome, model, predictor recall and precision, offset, cluster, survival fields), whether the model declines or asks when it should, replies containing numbers that are not in the context, and results by request type. *Lenient* match accepts only differences that change nothing in the engine. Inspect individual failures before choosing a deployment candidate; these metrics alone do not prove statistical correctness or safety.

## Release gates

Do not route production traffic to a candidate model until:

- The evaluation set is separated from training and contains reviewed edge cases.
- The model returns valid action JSON reliably and never creates unsupported variable names.
- All action parameters are validated server-side and again by the browser before execution.
- Requests to run analyses are checked against the actual loaded dataset schema.
- Regression tests confirm that model text cannot alter numerical calculations.
- Privacy, rate limits, abuse handling, latency and total cost are reviewed.
- The model card documents the training data, license, intended use, limitations, metrics and known failure cases.

## Data policy

The starter examples are synthetic. For future training, use only data that can legally be redistributed or used for training. Remove personal and confidential data. Do not train on identifiable research records, unpublished manuscripts, or patient-level datasets without explicit authorization and appropriate governance. Keep the held-out evaluation set out of training.

## Integration status

The browser app and its deterministic statistical engine remain the source of truth for numerical results. The local API adapter is opt-in through `window.QUANTAI_LOCAL_AI_URL`; without that setting, the existing Cloudflare Worker path remains unchanged. A local-model action must pass server-side validation and browser variable checks before the engine runs it.

## Local specialist model (no per-request LLM API)

The local inference path and training notebook are now available in this branch:

- [Colab training notebook](QuantAI_Training.ipynb): validate data, fine-tune, compare against the untouched base, and export a standalone model.
- [Local deployment guide](LOCAL_DEPLOYMENT.md): run the merged model behind a local FastAPI endpoint.
- [Local service](serve.py): inference runs from local weights, uses a local SQLite knowledge index, and does not call a third-party chat API.
- [Local response-guard tests](test_local_service.py): smoke tests for malformed JSON and unsupported actions.
- [Browser integration-contract tests](test_frontend_contract.py): static checks for local API request/response wiring and offset routing.
- [Knowledge base](KNOWLEDGE_BASE.md): research methods, test selection, interpretation and Ghana public-health context.

This removes per-request model API tokens when the service runs on your own machine or server. It does not remove hardware, storage, electricity or hosting costs. The current branch contains 93 synthetic training examples and 32 held-out synthetic evaluation cases. These are pipeline-development fixtures, not enough to claim expert-level or production-grade performance. Changes to the action contract and training data require a fresh Colab training, base-versus-fine-tuned evaluation, review of every failure, and export of a new merged model before the updated model can be tested. Do not assume the existing merged model includes the new offset examples.
